## 5. 작업 방법 (명령)

### 로컬 개발 환경 띄우기

지금은 Docker Desktop 이 꺼져 있다. 먼저 Docker Desktop 을 켜고 백엔드 컨테이너를 올린 뒤,
WSL 에서 프론트 개발 서버를 띄운다(`.claude/launch.json` 의 `alexview-win`, 포트 3100).

```bash
wsl -d Ubuntu -e bash -lc "cd /mnt/c/Users/user/Documents/woojeongalex.cloud/alexview && pnpm dev --port 3100"
```

### 검사(하네스)

```bash
wsl -d Ubuntu -e bash -lc "cd /mnt/c/Users/user/Documents/woojeongalex.cloud/alexview && npx tsc --noEmit"
```

백엔드는 컨테이너 안에서 **바꾼 파일에만** `ruff check`/`ruff format`, 그리고 `mypy apps/music_challenge`.

### 운영 배포

- 프론트: `main` 에 push 하면 Vercel 이 자동 배포.
- 백엔드: EC2 에서 `git pull` → `sudo DOCKER_BUILDKIT=0 docker build -t woojeongalexcloud-backend:latest .`
  → `docker compose -f docker-compose.aws.yml up -d --no-deps --force-recreate backend`.
  DB 스키마가 바뀌면 그 전에 `pg_dump` 백업 + `alembic upgrade head`.

### 곡 추가 절차

1. 로컬 컨테이너에서 `CreateChallenge`(음원 S3 업로드) → 리듬 채보 생성.
2. 로컬 DB 에서 곡 정보를 JSON 으로 추출.
3. EC2 `backend` 컨테이너에서 같은 JSON 으로 등록 후 채보 생성.
   로컬과 운영이 **같은 S3 버킷**이라 음원은 다시 올리지 않는다.
4. 운영 채보 생성은 **한 곡씩**. 첫 곡은 여유 메모리가 20~30MB 까지 떨어져 60~90초 걸린다(스왑).

## 6. 주의사항 (겪은 함정)

- **ruff 는 바꾼 파일에만.** 저장소 전체에 `ruff format .` 을 돌려 관련 없는 파일 342개가 바뀐 적 있다.
- **alexview 에는 eslint 설정과 prettier 가 없다.** 검사는 `tsc --noEmit` 만 가능.
- **WSL 에서 dev 서버 끄기**: `pgrep -f 'next dev'` 는 자기 bash 까지 죽인다.
  `pgrep -f "[n]ext dev|[n]ext-server"` 로 쓸 것.
- 서버를 도중에 끄면 `.next` 캐시가 깨져 500(ChunkLoadError). `.next` 지우고 다시 띄우면 된다.
- `/mnt/c` 에서 돌리는 dev 서버는 코드가 바뀌어도 자동 반영이 안 된다. **재시작해야 한다.**
- 로그인이 선택인 API 는 만료 토큰을 익명으로 처리한다. 그래서 `authFetch` 가 보내기 전에
  만료를 확인해 먼저 갱신한다(`alexview/lib/auth-client.ts`).
- 로컬 테스트 계정: `testuser1` / `Test1234!` (로컬 DB 전용 admin). 운영에서는 로그인되지 않는다.
- 로컬 DB 의 리듬 랭킹에는 확인용 테스트 기록이 몇 개 들어 있다(옛 판정 기준 점수 포함).
