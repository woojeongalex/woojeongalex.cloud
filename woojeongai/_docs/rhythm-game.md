# 리듬 게임 (오투잼식 떨어지는 노트)

원곡(보컬+반주가 섞인 완성곡) 하나로 채보 6개(4키·7키 × 쉬움·보통·어려움)를 자동으로 만든다.
스템·가사는 필요 없다. 노래방 모드(`challenge_charts`)와는 테이블·API 가 따로다.

## 흐름

```
[관리자] 스튜디오 "채보 만들기" → POST /challenges/{id}/rhythm/build (202)
[백엔드] 원곡 S3 다운로드 → librosa 분석(10~20초) → 채보 6개 → rhythm_charts
[브라우저] 헤더 "리듬 게임" → /rhythm (GET /rhythm/songs: 채보 있는 곡 목록) → /rhythm/{id}
           GET /challenges/{id}/rhythm/{keys}/{difficulty} → 노트 [time, lane, end|null]
           키보드(4키 방향키 ← ↓ ↑ → / 7키 A S D Space J K L)·터치 → 입력 기록 [lane, down, up]
[백엔드] POST /rhythm/{keys}/{difficulty}/plays → 같은 규칙으로 다시 채점 → rhythm_plays
```

## 판정 규칙 (서버·브라우저 공통)

- 판정 창: ±75ms COOL, ±130ms GOOD, ±185ms BAD, 밖이면 MISS. 빈 누름은 벌점 없음
  (2026-09-22 에 45/90/135 → 60/110/160, 2026-09-28 에 다시 75/130/185 로 넓혔다)
- 롱노트: 머리·꼬리 따로. 끝까지 누르면 꼬리 COOL, 일찍 떼면 그만큼 낮음. 머리를 놓치면 꼬리도 MISS
- 콤보는 BAD·MISS 에서 끊김
- 점수(최대 1,000,000) = 900,000 × 정확도 + 100,000 × 최대 콤보 / 판정 수,
  정확도 = (COOL + 0.6·GOOD + 0.2·BAD) / 판정 수
- 반올림은 JS `Math.round` 와 같게 `floor(x + 0.5)`
- 한쪽을 고치면 반드시 둘 다 고친다. 2026-09-22 무작위 입력 20판으로 두 구현의 결과가 모두 같음을 확인했다

## 채보 생성 규칙 요약

| 키·난이도 | 격자 | 최소 간격 | 초당 노트 | 박자 위계 | 롱노트 | 동시치기 |
|:--|:--|:--|:--|:--|:--|:--|
| 4키 쉬움 / 7키 쉬움 | 정박(4분) | 1박 | 0.8 / 1.0 | 가파름 | 다음 노트 전에 끝남 | 없음 |
| 4키 보통 / 7키 보통 | 8분 | 0.5박 | 1.5 / 2.0 | 완만 | 누르는 동안 다른 레인 노트 있음(동시 1개) | 없음 |
| 4키 어려움 / 7키 어려움 | 16분 | 0.5박 | 2.6 / 3.2 | 완만 | 동시 1개 | 마디 첫·셋째 박의 센 순간 (2% / 3%) |

### 박자 위계 (2026-09-28 추가)

노트를 고르는 기준은 **세기 × 마디 안 위치 가중치**다. 세기만 보면 조금 더 센 16분 엇박이
마디 첫 박을 이겨, 곡은 정박으로 들리는데 노트는 엇박에 깔린다. 그게 "헷갈린다"의 원인이었다.

| 자리 | 가파름(쉬움) | 완만(보통·어려움) |
|:--|:--|:--|
| 마디 첫 박 | 1.00 | 1.00 |
| 셋째 박 | 0.62 | 0.88 |
| 둘째·넷째 박 | 0.35 | 0.78 |
| 8분 엇박 | 0.22 | 0.42 |
| 16분 엇박 | 0.10 | 0.22 |

- 정박이 다 차야 엇박으로 넘어가므로, 밀도가 낮을수록 더 굵은 박만 남는다
- 쉬움은 가파른 위계로 규칙적인 펄스를 만들고, 보통·어려움은 완만해서 곡의 센 엇박이 살아난다
- 마디 첫 박은 비트를 넷씩 묶어 세기 합이 가장 큰 자리로 추정한다(4/4 가정).
  **격자가 아니라 비트에서 직접 세므로 같은 곡이면 난이도가 달라도 마디가 같다**
- 박자가 중간에 바뀌는 곡은 마디 추정이 맞지 않을 수 있다

### 비트 격자 보정 (2026-09-28 추가) — 가장 중요

librosa 의 onset 강도는 **봉우리**를 잡는데, 이건 실제 타격보다 두세 프레임(50~70ms) 늦다.
비트도 같은 강도에서 뽑으니 비트 격자 전체가 그만큼 늦어 있었다. 노트는 격자 위에 놓이므로
**모든 노트가 소리보다 늦게** 찍혔다. 이게 "노트가 소리보다 약간 늦다"의 원인이었다.

측정: 비트 ±6% 안에 드럼 타격이 있는 비율이 운영 곡 7개에서 **0~3.6%** 였다.

고친 방법 두 가지:

1. **소리 시작점 되돌리기** — `onset_backtrack` 으로 봉우리 앞의 골(실제 시작)로 옮긴다
2. **비트 격자 밀기** — 타악기 성분에서 드럼 타격을 뽑고, ±0.25박을 훑어
   드럼이 얹히는 비트가 가장 많아지는 보정값만큼 비트를 통째로 민다.
   보정값은 곡마다 다르다(운영 7곡에서 −48 ~ −91ms)

**허용 오차 하한(`_MIN_ALIGN_TOL` = 50ms)이 핵심이다.** 박길이 비례(×0.06)로만 잡으면
152BPM 곡에서 23.7ms 가 되어 분석 프레임 간격(23ms)보다 좁다. 그러면 프레임 하나 차이로
전부 걸러져 보정값이 아무렇게나 정해진다. 실제로 Stay 는 이것 때문에 비트 적중률이
14.1% 에 머물렀다(하한을 넣은 뒤 47.7%).

결과 — 곡별 비트 적중률과 채보의 드럼 일치율(±45ms):

| 곡 | BPM | 비트 적중 | 4키 쉬움 | 4키 보통 | 4키 어려움 |
|:--|:--|:--|:--|:--|:--|
| the sky | 92 | 93.3% | 94.8% | 89.7% | 89.5% |
| 가로등 | 89 | 80.7% | 86.6% | 84.1% | 83.8% |
| Sunlight Sparkle | 136 | 65.7% | 72.0% | 66.8% | 65.0% |
| My Memories | 129 | 65.2% | 62.8% | 63.0% | 64.6% |
| Close Enough | 162 | 64.1% | 63.8% | 60.6% | 61.3% |
| Still Here | 123 | 59.1% | 72.5% | 61.9% | 63.6% |
| Stay | 152 | 47.7% | 60.9% | 55.3% | 58.8% |

고치기 전에는 어느 채보든 드럼 일치율이 **2.7~6.3%** 였다.

### 해 보고 버린 것 (다시 시도하지 말 것)

- **중심 맞추기** — 창에 든 타격의 치우침 중앙값으로 한 번 더 밀기. 일치율이
  59.9% → 52.4% 로 떨어졌다. 훑기가 찾은 자리가 이미 최적이다
- **세기 가중 점수** — 보정값을 고를 때 드럼 세기를 더하면 소리 큰 후렴에 맞춰지고
  조용한 절이 밀린다. 개수로 세는 쪽이 낫다(평균 60.9% vs 62.8%)
- **드럼에 실린 소리를 노트로 우대** — 드럼 일치율은 그대로면서 정박·규칙성만
  단조롭게 떨어졌다(가중치 0→0.8 에서 정박 84.3%→74.4%). 격자를 제대로 맞추면
  정박이 곧 드럼 자리라서 따로 우대할 필요가 없다. 그래서 오래 저장만 하고
  안 쓰이던 `Onset.percussive` 필드를 없앴다
- **시간축 HPSS 드럼에 맞추기** — Stay 는 47.7% → 75.5% 로 좋아지지만 Sunlight 이
  65.7% → 47.0% 로 나빠진다. 어느 드럼 추출이 옳은지 단정할 근거가 없어 두지 않았다

### 남은 약점

빠른 곡일수록 격자가 덜 맞는다(92BPM 93% ↔ 152BPM 48%). 허용 오차가 절대값이라
박이 짧을수록 상대적으로 빡빡해서다. Stay 가 가장 나쁘다.

### 그 밖

- 세기는 주변 ±4초 안에서 상대값이라 조용한 구간에도 노트가 남는다
- 레인은 음이름을 곡 안 순위로 바꿔 배치(같은 음은 같은 쪽). 같은 레인을 0.4초 안에 다시 치게 되면 옆 레인으로 옮긴다
- 어려움은 격자가 16분이라 엇박에 노트가 놓일 수 있지만, 최소 간격이 0.5박이라 16분 연타는 나오지 않는다
- 2026-09-22 "너무 어려워" 피드백으로 밀도·동시치기를 낮추고 판정 창을 넓혔다
- 2026-09-28 한 번 더 낮췄다. 밀도 약 −25%, 어려움 최소 간격 0.25박 → 0.5박,
  보통의 동시치기 제거, 어려움 동시치기 비율 축소(7키 세 개 동시는 세기 0.99 이상만)
- 2026-09-28 박자 위계를 넣었다. 운영 곡 7개로 잰 결과(노트가 정박에 놓인 비율):
  4키 보통 67.5% → 89.0%, 4키 어려움 56.7% → 70.7%, 7키 보통 64.5% → 81.6%,
  7키 어려움 54.3% → 62.9%. 쉬움은 간격 규칙성이 42.4% → 61.7% 로 올랐다.
  느린 곡은 엇박을 쓸 수밖에 없어 정박 비율에 상한이 있다(7키 어려움은 상한 65.7%)
- 곡 #6·#7·#8 기준(9/22 프로필로 만든 채보): 쉬움 Lv.4~6, 보통 Lv.8~12, 어려움 Lv.10~15.
  9/28 프로필은 합성 분석(180초·100BPM)에서 Lv 가 2~4 낮게 나왔다 — 실제 곡은 다시 만들어 봐야 안다
- **프로필을 바꿔도 이미 저장된 채보는 그대로다.** 곡마다
  `POST /api/v1/challenges/{id}/rhythm/build`(admin) 로 다시 만들어야 새 규칙이 적용된다.
  다시 만드는 동안에도 이전 채보로 플레이는 계속된다. 판정 창은 저장물이 아니라 실행 규칙이라
  다시 만들지 않아도 바로 적용된다

## 알려진 한계

- 입력 기록은 브라우저가 만든다. 채보(GET)로 "완벽한 입력"을 합성해 보내면 막을 수 없다(노래방 모드와 같은 한계)
- 싱크 보정은 사용자가 설정(±300ms). 기기별 자동 보정은 없다
- 로그인 토큰이 만료된 채 제출하면 `authFetch` 가 먼저 갱신을 시도한다. 갱신도 실패하면 익명 기록으로 저장된다
